# 算式跑通，结论仍可能越界：在玻尔核查一段论文引用笔记

读论文时，AI找到了原文、运行了Python，是否就可以引用它给出的解释？我们用Strubell等ACL2019能耗论文，在玻尔科学空间实际做了一组同题阅读：普通提问仍认可“79.2小时是唯一解释”；加入核查流程后，唯一性问题改正了，却又把两点拟合当成了功率来源证据。第三行检验揭示了这个新问题。

本文解决一个明确问题：**怎样从论文表值走到有证据支持的引用句，而不把兼容计算写成作者内部事实？** 完整[论文PDF](INPUT/paper.pdf)、两组实际输入、完整最终输出、真实生成的三个脚本及作者核查均随包。不需要去GitHub或别的网站下载关键材料。笔记和外部电表是构造的阅读任务，未做新能耗测量。

## 先给读者可用的结论

表3的79、1507、1438是显示数值，必须把精确代入、取整兼容和来源识别分开。精确79小时不能复现后两列；在明示四舍五入假设下，79.2与79.21都兼容。换一种取整规则，候选是否通过、整个可行区间都可能改变。即使某个算式精确拟合两行，也不证明作者采用了那套共同参数。

能引用的是论文表列事实和带条件的计算。不能仅凭表中数值确定NAS功率沿用机制、作者舍入顺序或外部电表边界。下文展示这些判断怎样从实际AI输出、原文和独立复算中得到。

## 技术发现一：分别反解两个点，不是共同舍入兼容，更不是唯一性

固定表列合计功率与论文系数，得到：

```text
E(t) = 12041.51 × 1.58 × t / 1000 = 19.0255858t kWh
C(t) = 0.954 × E(t) = 18.1504088532t lb
```

A的[原始脚本](matched/A-verify_acl_energy.py)分别令E=1507和C=1438求出两个精确时长，却在最终答案中说“79.2 h 是唯一同时解释两个显示值的时长”。脚本运行成功不证明这个量词正确。

对非负round-half-up、能量/碳排步长1，两个输出分别约束E∈[1506.5,1507.5)、C∈[1437.5,1438.5)。反解到**同一个t轴**再求交，才是联合兼容。若表79和正文79.2也是相应精度的显示值，还需并入[78.5,79.5)与[79.15,79.25)。

| 明示假设 | 四约束共同区间，h，近似显示 | 精确候选79.2、79.21 |
| --- | --- | --- |
| 全部round-half-up | [79.19931785704994,79.23540519840393) | 都兼容 |
| 非负值全部截断 | [79.22686544586978,79.26168559813806) | 都不兼容 |

[作者Fraction精确核算](matched/author_verify.py)和[保存结果](matched/author-verification.json)包含严格分数端点，不用约数判断边界；Decimal只作显示。固定其他参数是条件，不把PUE1.58当当地实测。正文3.3天按同类一位小数显示约束不会进一步缩小这些交集。

B的[实际脚本](matched/B-verify_acl_energy.py)计算了第一种模型的区间，并检验精确79.2的截断，作者再补足第二种联合模型。因此不把作者补算写成B完成的步骤。精确79.2在截断下失败，与“显示79.2的[79.2,79.3)中仍有可行时长”不同；原文未给舍入实现，不能反推作者用了哪种。

另一个输入陷阱是两条路径都取整为192：201×0.954=191.754，未舍入201.1278696×0.954=191.8759875984。只看最终192会漏掉错误中间值。191.88/0.954=201.132075…并不精确等于201.1278696，只有舍入意义的近似；原脚本中的过强等号不采纳。

## 技术发现二：两点拟合把计算包装成了来源故事

B用T2Tbig(P100×8,1515.43W)和BERT(V100×64,12041.51W)，在没有原文支持共同参数的情况下，反解模型Power=a+g·b。两个点、两个未知数，当然可以精确拟合。B继而把NAS(g=8)也算回1515.43W，称为“同一采样功率”缩放。

这里漏了两步：P100与V100、负载和CPU/DRAM条件能否共享参数？这个模型能否预测未参与拟合、具有区分力的行？我们用实际表3的T2Tbase(g=8,1415.78W)检验：预测1515.43W，预测减表值为 **99.65W**。NAS与拟合点有同一个g，其零残差本身没有区分力；T2Tbase才反驳了把这一共同参数模型用于全表的说法。

[作者可运行反例](matched/probe_shared_power.py)保留原表转录、硬件标签、两个拟合残差、未参与拟合的预测和精确残差，输出[power-probe.json](matched/power-probe.json)。代码只检验这个明确的线性共同参数假设，不自动判断功率来源，也不宣称任何局部拟合都不可能。

随后在B同一会话追加[来源诊断问题](matched/B-repair-prompt.txt)，没有覆盖首答。实际[完整后续答复](matched/B-repair-answer-ax.txt)和新生成[脚本](matched/B-acceptance.py)接受了99.65W反例，但又说实际生成方式“逐行各自取功率”，仍试图将沿用写成支持的推断。**否定一个模型不能证明另一个来源机制。** 这部分明确不采纳，后续答复也不算进前面的首答配对矩阵。

最终允许的引用句是：表3中NAS与T2Tbig的功率显示相等；同为P100×8的T2Tbase却不同。全表共享同一组a、b的模型被该反例否定；这些事实仍不足以确定NAS表值的来源与作者内部操作。

## 又一类边界：相同电量，不同文章采用不同因子

为核查来源，作者另查了同作者的AAAI2020扩展文章（不同题名，DOI10.1609/aaai.v34i09.7123）。[本地必要原文片段与来源](version-check/README.md)显示：其PDF第2页式(2)用0.477，第3页Table2的BERT电量仍1507kWh、排放改为719lb。ACL2019则用0.954，第4页Table3给1438lb。两份表的相同能量显示不能抵消因子和假设的差异。

作者先实际读源文并复算，再在B对话追加[版本核查问题](version-check/prompt.txt)，只提供2020合法有限片段及标明的作者概述，没有声称模型收到全文或自己检索。该问题明确询问：能否把2020当成2019笔误修正？排放减半能否证明硬件节能？追加仍在同一B上下文，不算入前面冻结首答比较。完整实践和作者判定见version-check/README.md。

独立Fraction复算表明：显示1507乘0.954为1437.678，乘0.477为718.839；79.2小时路径的未舍入能量是1506.82639536，对应1437.51238117344与718.75619058672。两种路径分别可舍入到1438/719，但不识别作者内部路径。0.477是0.954的一半，条件换算值减半并不提供新的实际能耗测量；这些材料也没有确立勘误。引用必须明确“哪篇文章、哪张表、哪个因子及假设”，而不是只锁题名关键词或同作者。

## 在玻尔怎样照着做

1. 文献阅读→本地导入INPUT/paper.pdf，确认6页与题名。打开阅读助手，新建A对话，发送matched/task.txt，等最终输出完成并保存原答、表格、脚本。不要将A的回答复制给B。
2. 在同一篇论文中点击“新建对话”，核对仍为标准模式。发送matched/B-prompt.txt，它等于task.txt加一个换行再加workflow.txt。它不包含标准数值答案；不过流程与题目针对已知难点，不能称无泄漏盲测。
3. 对照PDF第2/3/4页，用冻结八项标准逐条标出原句。不能只看最后的“可引用”标签。检查生成脚本实际在做精确值求解、区间求交还是来源猜测。
4. 若出现从拟合倒推来源，保留首答，用B-repair-prompt.txt组织后续诊断。先找未参与拟合且能区分假设的记录；若无记录就标不可检验，不能编造数据。
5. 把作者的采纳、拒绝与仍未知单独写出；不要拿修订覆盖原始失败。一般设备名称不能代替物理边界；外部电表还缺起止时段、下游负载、任务归属和适用因子。平均/边际因子的选择取决于核算目标，不统一要求边际因子。

[截图A](matched/A-final.jpg)、[截图B](matched/B-final.jpg)显示实际阅读界面，[操作与来源记录](matched/provenance.json)保留输入、设置、哈希及局限。AX是可见最终答复快照，不是完整原生模型遥测；动态文本字段会截断B问题显示，完整已提交提示另存B-prompt.txt，原输入框粘贴后已核对。隐藏处理过程未作为证据发布。

若解析结果缺正文，不能只凭“解析完成”继续猜。先核对原PDF是否存在和可读；有本地文件权限时可用pdftotext -layout提取，保留PDF页码、表头与上下文；没有材料就停止。生成脚本的具体存放位置在本次会话不同，不要照抄作者本机绝对路径，下载实际交付文件再运行。
