# Strubell 等（ACL 2019）能耗与碳排阅读审计

**引用判断：不能引用“一个 Transformer 模型产生 626155 公斤碳排”。** 所供论文 Table 1 的 626,155 属于“w/ neural arch. search”，Table 3 对应 NAS 的 GPU 情景，单位为 **lb CO₂e**，约 **284,019 kg（284 吨）**；它是完整架构搜索预算的估计，不是单个最终模型一次训练的实测排放。Table 1 的 Transformer big 单次训练另列 **192 lb，约 87.09 kg**。两处混淆分别涉及质量单位与预算范围。

可改为：“Strubell 等（2019，Table 1、3）在其功率外推、PUE=1.58 和美国平均排放因子假设下，估计该神经架构搜索的 GPU 等效情景排放约 626,155 lb CO₂e（约 284 吨）；同表 Transformer big 一次训练估计约 192 lb。”不可把 GPU 等效情景说成对原 TPU 搜索全过程的电表测量，也不可推广为所有 Transformer 的固定排放。

## 方法：哪些是测量，哪些是外推

作者用默认设置运行开源模型，最多一天；除 ELMo 使用3张 GTX 1080 Ti 外，方法称其余模型在单张 Titan X 上运行。GPU 用 nvidia-smi 反复采样，CPU 用 Intel RAPL；公式还包含所有 DRAM sockets 的平均功率。文中未充分交代 DRAM具体采集、采样间隔、同步方式、各分项读数、跨设备校准和原始序列，因此不能独立验证完整功率估计。

作者随后用原论文报告的完整训练时长和硬件外推。并非在 Table 3 的每一种硬件上做了全程测量：例如该表 ELMo 标 P100×3，正文引用原训练为 GTX 1080×3，本地采样则为 GTX 1080 Ti×3；BERT 表列 V100×64，而通用测量段称单 Titan X。材料不足以复原这些硬件之间具体的功率缩放规则。应将表中功率视为作者估计输入，而非已验证的对应目标机器电表读数。

按式(1)，若平均功率单位为 W，时间 t 为 h：

\[
E_{IT}=t(p_c+p_r+g p_g)/1000,\qquad
E_{facility}=1.58 E_{IT},\qquad
C_{lb}=0.954 E_{facility}.
\]

其中 CPU、DRAM 各项已是全部 sockets 的总和，GPU项才是单卡功率乘卡数。Table 3 的 Power 列按总 IT 功率解释可复现除BERT显示精度问题外的数值；**不得再乘表内8、3或64张卡**。这是由公式和表值支持的口径判断，不是底层测量完整性的证明。

W/kW 是功率，Wh/kWh 是能量；除1000是W到kW，乘小时才成为kWh。原文把式(1)的结果称为某时刻“power”，但公式已乘时间，其量纲实际是能量。应区分术语不严谨与数值公式量纲：只要 t 用小时，该式可以计算kWh。

PUE=1.58 是作者采用的2018全球数据中心平均值，意在覆盖冷却等设施支持开销，不是目标训练现场实测PUE。`kWh·PUE` 一列已乘该系数，不能再次乘。0.954 的单位是 **lb/kWh**，约 **0.43272712098 kg/kWh**，来源为作者引用的美国EPA平均值；不是0.954 kg/kWh，也不是普遍适用或本地当前因子。论文借能源结构与AWS近似来说明合理性（第2–3页），这不验证具体区域、时段或云作业的排放。这里核算的是用电相关估计，未提供设备制造等全生命周期隐含排放，亦未据此证明碳抵消或边际减排。

NAS推导另有一层：第3页报告979M搜索步，基模型在一个TPUv2 core上300k步需10h，比例约为32,633.33h；正文与表列32,623h，不能由这两项显示数精确复原（可能受原始步数精度等影响，未取得原始值）。GPU等效值274,120h可由979M/300k×84h得到。该84h与big训练时长一致，显示了按训练步骤映射的估计口径；材料未证明不同搜索候选、硬件与提前停止阶段都有相同每步耗能。该时长搭配8卡合计功率，属于8卡配置等效运行小时，不能再按“单卡GPU小时”重复乘8。

**差异如何判断：** 除BERT外，名义结果按整数四舍五入均得到印刷能耗和排放。BERT按79h的两项结果均无法得到表值，此项失败保留，不能静默改为79.2。正文明确给79.2h，用它复算得到1506.82639536kWh和1437.51238117lb，四舍五入可得1507和1438。因此有来源支持“小时显示精度能解释差异”，但无法据此断言作者的内部计算就是如此，也不应武断认定表中科学估计已获验证。

进一步做了显式条件检查：假设功率按0.01W、输出按1kWh/1lb四舍五入，固定表内小时，只有BERT两项区间不重叠；再假设小时也按1h舍入，则五行两项均兼容。PUE和排放因子在这些检查中固定，未假装知道它们的原始精度。区间仅是这些显示舍入假设下的上下界，**不是测量误差、置信区间或统计不确定度**；兼容表示未被假设排除，不表示证明了计算或科学含义。

单独拿印刷能耗乘0.954，依次得到25.758、191.754、262.350、1437.678、626155.038lb，均可四舍五入至所列排放。不能据此认定作者先取整能耗再计算排放，两列也可能分别从未显示的中间值取整。TPU的BERT、NAS及GPT-2三行没有功率资料，不能核算能耗或排放，更不能以破折号作为零或给出GPU/TPU排放高低排名；云价格便宜也不直接证明碳排更低。

## Table 4：一次训练、调参和完整研发不能混用

Table 4 的三行是LISA案例的不同预算：单模型120h、一次调参估计24次作业共2880h、完整R&D 4789个作业共239,942h。第4页日志描述跨172天、123个小网格搜索，作业最短3分钟（崩溃）、最长9天，称平均52h；用表值相除实际约50.10h，故平均数也存在未解释的口径/数值差异，不能只用舍入到整数小时解释。9998 GPU天换算为239,952h，与表值相差10h，若“天”显示取整数则可兼容，但未取得原始日志。

239,942/(172×24)≈58.13，是约58张GPU持续占用的等效量，与“about 60 GPUs”相符；既不是项目运行了27个墙钟年，也不是所有作业同时运行。120h是单次完整训练预算，24×120=2880是调参情景；不能用4789×120=574,680h代替实际累计日志时间，因为作业长度不同，包含崩溃等短作业。三行也不能相加冒充同一项目总账。

表列云费用为$52–175、$1238–4205、$103k–350k；电费为$5、$118、$9870。脚注8说明本地Titan X（72%）/M40（28%）用P100云价近似，脚注9用美国$0.12/kWh。云费用范围是租价情景而非统计置信区间；电费不等于云账单，也不等于含购置、运维的全部成本。反推$9870/0.12=82,250kWh，再除239,942h约0.3428kW，最多是表内费用隐含的平均电量率；论文没有给出足以独立复核Table 4的分项功率与PUE处理，不能将该反推当作实测值。

Table 1 的pipeline单次39lb、含调参与实验78,468lb，约相差2012倍；这不等于简单乘4789。后者按0.954lb/kWh和$0.12/kWh可得约$9870，与Table 4研发电费近似一致，属于表间算术交叉检查，不能证明硬件归因或测量模型正确。

## 用户本地训练：两组数据怎样使用

已知8卡**合计平均IT功率**1.51543kW、84h：

- IT能量=1.51543×84=**127.29612kWh**，不再乘8。
- 条件性照搬论文PUE：设施估计=127.29612×1.58=**201.1278696kWh**。
- 再条件性照搬论文美国因子：**191.8759876lb≈87.033484kg CO₂e**。这是“按论文假设的估计”，不是已确定的本地实际排放。

必须确认“IT功率”是否已含CPU、DRAM及本次作业应分摊的其他IT用电。如果实际上只是8张GPU之和，127.29612只是GPU能量，不能直接称完整IT总能耗，也不能凭现有资料补出缺失项。

另有**设施电表201kWh**：若它覆盖同一次训练、同一时段和对应设施边界，并已正确归因给该作业，可直接作为设施能耗使用，**不能再乘PUE**。按相同历史因子条件计算为201×0.954=**191.754lb≈86.978151kg**。不能把它与IT能量或201.1278696再相加，它们是同一用电过程的不同边界或不同取得方式。

若两组数据确实边界匹配，比值201/127.29612≈**1.5789955**可作为该时段隐含的设施/IT比；两种设施能量相差0.1278696kWh（约0.064%）。这既不证明采用全球1.58一定准确，也不能凭近似相等断定电表校准、CPU覆盖、时间积分、作业归因都正确。任务未给电表分辨率及误差，不把显示整数201自动当已知精度。若201包括其他作业或整栋设施，则其归属于该训练的份额尚未知，这个比值也不能作为有效PUE。

本地真实碳排还缺地点、时间、适用电力因子及其生产/消费与核算边界。现有数据能约束用电，却不能单独确定实际kg CO₂e。若有分时数据，应使用Σ(Eᵢ×Iᵢ)或等价的能量加权因子；不能任意用时间平均碳强度乘总电量。账本特保留“设施能量已知、实际排放unknown”的记录。

## 后续引用与测量建议，以及未解决问题

引用时同时给模型版本、单训/调参/搜索/R&D预算、GPU等效或实际硬件、能量边界、PUE与排放因子来源和年份；将“估计”保留在措辞中。Table 1 的日常生活比较只用于量级背景，其外部基准及边界本次未独立验证。

下一次测量应保存完整作业开始结束时间、功率序列及采样间隔、积分方法、硬件数量和型号、CPU/DRAM/GPU覆盖、空闲基线如何处理、计量误差和电表边界。记录失败和提前停止的作业，将单次训练与完整实验账本分别汇总。在共享主机上按利用率分摊是归因假设，CPU、DRAM、GPU可能需不同权重；不能让多个进程各认领整机功率而双计。设施电表若服务多个任务，须给出分摊依据；PUE仅在IT到设施转换时使用一次。

仍需作者原始功率日志、跨硬件外推/分项缩放规则、未取整时长与能耗、NAS原始搜索步数及映射、LISA逐作业日志与电费推导，才能解决本文保留的问题。本地还需IT覆盖、电表归属、时间对齐、精度与适用排放因子。未取得这些材料，不将算术差异自动判为论文错误，也不将舍入兼容解释为作者方法已被证实。
