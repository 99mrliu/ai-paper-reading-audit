# Strubell 等（ACL 2019）论文阅读审计

审计对象：随附《Energy and Policy Considerations for Deep Learning in NLP》六页 PDF。下文同时标记 PDF 页序和印刷页码；仅使用该文件及题设数据，未联网核查被引文献、原始训练日志或电网数据。事实指论文明确报告的内容，不表示已由独立实验确认。条件推导指在所列假设下的计算。算术或字面一致，不证明硬件迁移、工作负载或科学解释有效。

## 1. 待引用句的结论

“一个 Transformer 模型产生 626155 公斤碳排”不应使用，至少混淆了单位、预算范围和证据性质。

- **单位**：Table 1（PDF 1 / 3645）明确标注 `CO2e (lbs)`；Table 3 图注（PDF 4 / 3648）也写 `CO2 emissions (lbs)`。626,155 磅约为 **284,019 公斤（284 吨）**，并非 626,155 公斤。这里是论文所称 CO₂e 质量，不是元素碳质量。
- **预算**：Table 1 将 192 放在 `Transformer (big)`，626,155 放在其下的 `w/ neural arch. search`；Table 3 后者位于 NAS、P100×8、274,120 小时一行。它代表搜索过程的累计计算预算估计，不是最终单个模型的一次常规训练。相同表内 T2Tbig 的 84 小时训练估计为 201 kWh、192 磅（约 87.1 公斤）。
- **性质**：这些是短时功率采样、文献训练时长、硬件换算、PUE 和美国平均排放因子共同形成的估计，不是搜索现场连续电表或排放实测。NAS 的 GPU 行还是从 TPU 搜索预算换算的情景；不能将其说成实际 TPU 搜索的已测排放。

建议引用：“Strubell 等（2019，Table 1、3）在其硬件换算及平均能效、排放因子假设下，估计一次 Transformer 神经架构搜索的 GPU 等效计算预算对应约 626,155 磅 CO₂e（约 284 吨）；这一数字涵盖搜索预算，不代表单个 Transformer 的一次训练。”同时可列出 T2Tbig 的 192 磅作为预算口径对照。

## 2. 方法链：测了什么，又外推了什么

方法节在 PDF 2 / 3646，模型和时长来源在 PDF 3 / 3647。

| 环节 | 论文报告 | 审计判断与限制 |
|---|---|---|
| 短时运行 | 默认配置训练，`maximum of 1 day`；除 ELMo 用 3 张 GTX 1080 Ti 外，使用单张 Titan X | 是本地短窗口，不是表内所有配置、全部训练周期的直接测量 |
| GPU 功率 | 重复查询 NVIDIA System Management Interface，报告样本平均 | 是功率遥测；缺采样间隔、时间加权细节、波动和误差范围，不能确认窗口代表完整训练 |
| CPU / 内存 | CPU 采用 Intel RAPL；公式另定义所有 CPU sockets 的平均功率和所有 DRAM sockets 的平均功率 | 正文没有单独交代 DRAM 采样实施细节，也没有各分量读数；不能补称已完整测量整机所有器件 |
| 完整训练时长与设备 | 取原模型论文等报告的硬件与时间 | 属于外部报告和外推，不是本次连续计量；跨卡型和规模迁移缺少详细标定 |
| 设施开销 | 采用 2018 年全球数据中心平均 PUE 1.58 | 是假设，非目标机房 PUE 实测；主要计入冷却等支持设施 |
| 排放 | 式 (2) 使用美国平均 0.954 lb/kWh | 是电力相关排放估计，非训练地点和时段的实测排放；不等同完整生命周期足迹 |

式 (1) 用清晰单位重写为：

\[
P_{IT}=p_c+p_r+g p_g\quad[W],\qquad
E_{facility}=\frac{P_{IT}\,t\,1.58}{1000}\quad[kWh],
\]
\[
C=0.954\ E_{facility}\quad[lb\ CO_2e].
\]

其中 t 必须以小时计；p_g 是单卡平均功率，g 是卡数；p_c、p_r 已分别是所有 CPU、DRAM 插槽的合计，不能再随 g 整体倍乘。若已经知道设备合计功率，也不能再乘卡数。论文把含有时间的结果称作 power、记为 p_t，措辞不严谨；按量纲它是能量。W、kW 表示功率，kWh 表示能量，PUE 是无量纲比值。

Table 3 的 Power 列按合计 IT 功率解释可以得到下节结果；不能把 1515.43 W 当单张 GPU 再乘 8。严格地说，论文没有提供分量账本来逐项验证该列是否完整覆盖公式中的全部负载。

硬件外推尤其需谨慎：Table 3 写 T2T 的 P100×8、ELMo 的 P100×3、BERT 的 V100×64；本地采样设备却是 Titan X / GTX 1080 Ti。ELMo 的源训练描述又是 GTX 1080×3。本文并未清楚给出这些卡型之间功率与吞吐量的换算细节。因此“按表值可复算”不等于“在这些目标硬件上已直接测得这些功率”。训练能耗也未明确覆盖存储、网络、器件制造、全部推理部署等生命周期项目。

美国因子的理由是作者认为美国能源构成与 AWS 相近（PDF 2–3，Table 2 及续文），不是其证明了每次训练的实际电力来源相同。Table 2 的能源百分比不能单独给出任一地点的排放因子。本文不以该历史因子宣称本地当前实际排放。

示例完整代入：T2Tbig 的能量为 `1515.43 × 84 × 1.58 / 1000 = 201.1278696 kWh`；排放为 `201.1278696 × 0.954 = 191.8759875984 lb`。

**通过的名义检查**：T2Tbase、T2Tbig、ELMo、NAS 的能量和排放在末步四舍五入后均与表中整数一致。这仅说明给定输入与公式的算术关系吻合。

**保留的未通过检查：BERT 按印刷 79 小时无法复现表值。** 四舍五入应得 1503 kWh、1434 lb，而非 1507、1438，不能仅称作输出整数取整误差。正文（PDF 3 / 3647）明确写 NVIDIA 的 GPU 训练为 `79.2 hours`。改用该时长得到：

- `12041.51 × 79.2 × 1.58 / 1000 = 1506.82639536 kWh`，取整 1507；
- 再乘 0.954 得 `1437.51238117344 lb`，取整 1438。

因此“计算保留了正文的 79.2 小时，表格时长显示为 79”是有明确文本依据的解释。没有作者计算工作表，不能把这一解释当作已确认的内部计算路径，也不宜武断断言是能耗计算错误。单用表中已取整的 1507 kWh 再乘因子得 1437.678 lb，也取整为 1438，无法辨别作者究竟在哪一步取整。

**另外保留的搜索时长问题**：PDF 3 / 3647 写搜索 979M steps，300k steps 需要 10 小时，据此直接算出 `979000000 / 300000 × 10 = 32633.333` TPU 核小时；正文及 Table 3 却写 32623，相差约 10.33 小时。输入的 979M、10 小时可能已经取整，也可能另有转录或计算问题；现有材料无法判定。按 84 小时/300k steps 得 `979000000 / 300000 × 84 = 274120`，与 GPU 行相符。但用不同硬件、模型和训练步骤等效估预算所需的吞吐量可比性，不能由这项乘法得到证明。

设备小时和墙钟小时应分开：Table 3 的 GPU NAS 是在 8 卡配置下的 274,120 小时等效预算，对应 2,192,960 GPU·小时；表内功率已是合计，算能量不能再乘 8。这也不是说原搜索按该配置连续运行了约 31 年。实际并行度会影响日历时间。TPU 的 core、chip 口径亦不宜凭表中“×1”自行当作与一张 GPU 同义。

BERT TPU、NAS TPU、GPT-2 TPU 三行没有功率。图注明确说因缺乏公开功率信息而省略，故不能复算能量或排放，更不能把破折号当零。云费用比较也不能替代其排放比较。

## 4. Table 1 与 Table 4：预算不应混用

Table 1（PDF 1 / 3645）把日常活动、一次训练和研发预算并列作量级对照；它们不是边界完全相同的生命周期核算。Transformer 的 192 与 626,155 相差约 3261 倍，反映表中的单次训练与搜索预算差异，不能推广成“每个模型必须排放这么多”。NLP pipeline 的 39 与 `w/ tuning & experiments` 的 78,468 同样属于不同范围。

Table 4（PDF 4 / 3648）是 LISA 案例，不是 NAS 或 BERT。图注把三行定义为单模型、单次调参、全部研发：

| 预算范围 | Models（作业数） | Hours | 云计算 USD | 电费 USD |
|---|---:|---:|---:|---:|
| 单次训练 | 1 | 120 | 52–175 | 5 |
| 一轮调参 | 24 | 2880 | 1238–4205 | 118 |
| 全部研发 | 4789 | 239942 | 103k–350k | 9870 |

正文 §4.2 明确报告 172 天内做了 123 次小型超参数网格搜索，共 4789 个作业；从失败崩溃的 3 分钟作业到 9 天作业均包括，设备占比 Titan X 72%、M40 28%。这批研发日志是作业数量和累计时间的依据，不能称它们都是成功训练或同样长的最终模型。单次调参的 24 个作业是作者的估计；2880 正好等于 24×120。123 轮历史搜索并不等于 123×24，也不等于全部作业具有统一训练预算。

Hours 为累计计算时间，不能把 239,942 小时当成 172 天中的墙钟时间。约 9998 GPU 天折合 239,952 小时，和表值差 10 小时，符合天数取整的可能性；9998/172≈58.1 张 GPU 持续运行，与“about 60 GPUs”量级一致。另有未解决的不一致：正文声称平均作业 52 小时，但表值除以 4789 为约 50.10 小时。仅靠整数小时取整不能解释这一差距；缺少逐作业日志，不能确认分母、筛选口径或笔误，也不据此擅自改写表值。

费用有三种不同含义：云费用是按实例/设备时间与价格估计；原始电费是按用电量和电价估计；购机支出还属于另一口径。Table 4 脚注 8 说用 P100 价格近似实际 Titan X/M40 的云成本；脚注 9 用美国平均电价 `$0.12/kWh` 计算电费。云价格上下界对应抢占式与按需价格（PDF 3 脚注 7），不是功率或排放的统计置信区间。不能将云费用和电费直接相加作为同一服务的账单，也不能把购机成本与单次云租价直接当作相同预算。

条件性核对：9870 美元 / 0.12 = 82,250 kWh，再乘 0.954 为 78,466.5 lb，与 Table 1 的 78,468 极近。因电费本已取整，这支持二者预算量级相符，但不能恢复精确底稿。该能量除以 239,942 小时隐含约 0.34279 kW 的平均设施功率；没有分量功率和逐作业能耗，不能独立确认它如何得到。单模型 5 美元 / 0.12 × 0.954 = 39.75 lb，不能从已取整的电费精确推出 Table 1 的 39；不要据此强行认定某一表错。Table 1 的研发碳数是估计，Table 4 的工作日志并不是设施电量实测。

## 5. 本地训练的两组数据怎样使用

题设是“8 张 GPU 的合计平均 IT 功率 1.51543 kW，84 小时”，另有设施电表 201 kWh。关键缺项是：这里的 IT 功率究竟只覆盖 GPU，还是已包括主机 CPU、DRAM 等？以下把两种解释分开，不能因数值恰好与论文相同而默认边界相同。

### 5.1 条件 A：1.51543 kW 已是完整相关 IT 合计功率

无需再乘 8，也无需再除 1000（功率已经是 kW）。依论文参数：

\[
E_{IT}=1.51543\times84=127.29612\ kWh,
\]
\[
E_{facility,est}=127.29612\times1.58=201.1278696\ kWh,
\]
\[
C_{est}=201.1278696\times0.954=191.8759876\ lb
=87.033484\ kg.
\]

这是“采用论文 PUE 与美国历史平均因子得到的估计”，不是本地真实排放的测定值。与 Table 3 T2Tbig 算术一致也不能证明该本地运行就是论文模型或具有相同效率。

### 5.2 条件 B：该功率仅是八张 GPU 的合计

可以确定 GPU 能量为 127.29612 kWh；无法据此完整应用论文的 CPU+DRAM+GPU 公式。若遗漏部分的平均 IT 功率为 q kW，则按同样假设设施能量为 `(1.51543 + q) × 84 × 1.58`，排放再乘 0.954。q 未知时，87.03 kg 仅是 GPU 边界扩展后的条件估计；不能称完整训练碳足迹。若 q≥0 且 PUE/因子固定，它是这一特定模型的下界，但不是实际设施排放的一般下界，因为真实 PUE、供电结构仍未知。

### 5.3 设施电表 201 kWh

若电表确实覆盖同一训练的同一 84 小时、全部相关设施用电，且没有未分摊的其他作业，则直接使用 201 kWh，不再乘 PUE。按论文历史因子换算为：

\[
201\times0.954=191.754\ lb=86.978151\ kg.
\]

不能把电表数与 201.1278696 kWh 相加或取平均作为训练用电；它们是同一目标量的不同证据路径。重复乘 1.58 会把设施开销重复计入。

在条件 A 和相同计量边界成立时，比值 `201 / 127.29612 ≈ 1.5789955` 可作为该运行的有效设施/IT 能量比，接近 1.58；两者相差约 0.128 kWh。但缺少电表精度、计量边界和独立性信息，不能判断差异显著与否，也不能据此验证全球平均 PUE。若分母只是 GPU 能量，该比值混入 CPU 等负载，不能直接叫 PUE。

若电表覆盖整机房其他用户、空闲基线或不同时间范围，则只能确认该表覆盖范围内记录了 201 kWh，不能全归于此次训练。应先按明确规则分摊；题设没有提供分摊依据。即使训练电量已确认，本地实际排放仍需要适用的时空排放因子和核算边界。这里无需查询当前因子，也没有足够资料判断本地真实排放是多少。

## 6. 对后续引用和测量的建议

引用时同时列明模型、一次训练/调参/搜索/研发的范围、硬件、累计设备时与墙钟时、能量、PUE、排放因子及质量单位，并用“估计”限定该论文数字。保留 BERT 的印刷时长复算失败及正文 79.2 小时解释；不要悄悄修表。报告 NAS TPU 时长和 LISA 平均作业时长的未解决差异。

本地记录应保留 GPU、CPU、DRAM 的测量覆盖，采样时间戳与功率序列，完整训练区间和失败重跑；对不等间隔样本用时间积分，而非不加权样本平均。最好取得同边界的 IT 与设施能量记录，说明共用服务器和空闲功耗的分摊方式及电表精度。实测设施能量与 PUE 外推值分别报告。排放另列因子、适用地点与时间，避免把一项电力估计写成完整生命周期结论。

当前可确定的是表内单位与预算归属、按给定公式的复算结果和两组本地数据的条件计算；不能确定的是作者所有内部换算、完整采样代表性、目标硬件实测有效性、研发功率底稿和本地真实排放。上述缺项不以推测补齐。
