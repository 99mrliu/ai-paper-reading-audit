# AI找对了引文，为什么还会讲错原因？一次玻尔科学空间论文核查实录

同一个表格、同一套公式，AI找到了页码，仍把“能解释”写成“只有这个解释”。追问后改了唯一性，却又把两个不同输入的乘法混在一起；再换成“五栏核查”，还会把“高置信”改名为“B级强推断”，没有补足证据。本文用一篇6页论文，展示怎样把这样的答案核查到可以引用，以及哪些判断必须停止。

论文是Strubell、Ganesh、McCallum的 *Energy and Policy Considerations for Deep Learning in NLP*，ACL2019，P19-1355，pp.3645–3650。完整[原PDF](INPUT/paper.pdf)、[来源与授权](SOURCES.md)、实际输入输出和独立计算均在包内。没有训练模型或测量新能耗；外部电表是明确标注的假设输入。

## 阅读问题：四种“相符”不能混成一种

Table3的BERT行写12041.51W、79h、1507kWh、1438lb；正文写79.2h。问题不是给它编一个合理解释，而是分开检查：

1. **精确复算**：将表列79当精确输入，是否真的算回1507/1438？
2. **显示兼容**：若数字经过取整，是否存在同一个时长，同时产生所有显示值？
3. **唯一解释**：79.2可兼容，能否排除79.21等其他时长、其他取整规则？
4. **来源事实**：算术上可复现一条路径，是否证明作者实际采用该路径？

第一项失败，不代表第二项必然失败；第二项通过，不证明第三、四项。实际回答的失误就在这些跃迁之间。

## 为什么这样组织原文和上下文

先读[PDF第2页方法与公式](out/source-page-2.png)，确认PUE1.58、美国平均因子0.954lb/kWh及IT功耗边界；再读[第3页BERT/NAS段](out/source-page-3.png)，确认79.2h来自正文引用；最后看[第4页完整表图](out/table3-page4.png)，保留模型、硬件、表头、单位和表注。只裁一行容易把合计功率再乘64，或把NAS全搜索误读为单次训练。

固定表列合计功率与上述系数：

```text
E(t) = 12041.51 × 1.58 × t / 1000 = 19.0255858t kWh
C(t) = 0.954 × E(t) = 18.1504088532t lb
```

方法段只说明最多一天的功率采样，完整训练时长另有来源。功率、累计能量和碳排估计是不同量；公式中含时长，不能因为原文某处称其power就丢掉时间维度。表列功率在本次条件计算中按合计IT功率解释，不再乘GPU数量；跨硬件的功率来源映射仍缺底层日志。

## 技术方法：从“写得像核查”到可以反驳

五栏分别承担不同任务：**声明**拆成可反驳的小句；**原文**记录页码和必要上下文；**算式**区分显示输入、未舍入输入及中间步骤；**边界**明示物理口径、共同参数和取整假设；**判定**只能使用已经有证据支持的强度。

它不是自动正确的格式。第三轮填齐五栏，却在总结中越界。第四轮因此多加两道检查：为“作者采用某来源”提出仍未被排除的替代机制；为“换规则结论不变”分别算出两种模型，核对不变的是存在性、候选判定还是整个区间。可读性和真实性分别验收。

### 发现一：相同的最终整数会遮住错误乘法

作者独立精确核算：

| 计算路径 | 结果lb | 整数显示 | 可以据此说什么 |
| --- | ---: | ---: | --- |
| 显示201 × 0.954 | 191.754 | 192 | 否定第二轮191.88这条乘法 |
| 未舍入201.1278696 × 0.954 | 191.8759875984 | 192 | 另一条也能得到192的兼容路径 |

未舍入能量由1515.43×84×1.58/1000得到。两条路径的最终整数相同，所以只验最终192会漏掉错误；也不能倒推出作者采用哪条路径。第四轮明确撤回第三轮“表内192由未舍入值得到”的事实语气。本文只认可**可复现路径**，作者内部顺序仍未知。

### 发现二：取整约定改变候选是否兼容

用非负round-half-up、输出步长1、正文时长步长0.1，且功率、PUE和排放因子固定；碳排直接由未舍入能量计算。各约束先反解到同一时长轴，再取交集，不能为不同输出各挑一个时长。

```text
表79       → t ∈ [78.5, 79.5)
正文79.2   → t ∈ [79.15, 79.25)
能量1507   → E(t) ∈ [1506.5, 1507.5)
碳排1438   → C(t) ∈ [1437.5, 1438.5)
```

[作者侧Fraction核算](science-space/author_verify.py)保留精确分数，Decimal只作显示：

| 假设模型 | 四约束的共同t区间（h，近似显示） | 精确候选79.2 / 79.21 |
| --- | --- | --- |
| 全部round-half-up | [79.19931785704994, 79.23540519840393) | 均兼容 |
| 非负值全部截断 | [79.22686544586978, 79.26168559813806) | 均不兼容 |

两者都存在解，但区间不同。正文显示“79.2”与精确候选t=79.2也不同：截断模型允许真实t在[79.2,79.3)，所以不排除其中79.24等兼容值。不能把“精确79.2不通过”写成“显示79.2整段不通过”。正文另写3.3天；若同样按一位小数显示取整，其时长区间覆盖本表交集，不再缩小结果。

名义精确79始终保留失败：1503.0212782kWh、1433.8822994028lb；half-up下79.2给1506.82639536、1437.51238117344，79.21给1507.016651218、1437.693885261972。反例否定唯一性，不证明原作者用过反例。这里是条件可行集，不是测量置信区间；原文未给取整实现，不能从可行性判定其实际规则。

### 发现三：换置信标签不等于补证据

第三轮将“高置信沿用T2Tbig”改成“B级强推断”，证据没有增加。第四轮列出共同参考来源、硬件估算、独立值舍入相同、直接沿用等替代解释后撤下该标签。它列出的机制是**假设**，没有任何一种成为作者事实，也未证明概率排序。

作者复核另指出第四轮一处过宽例子：“填到所有P100×8行”与Table3的T2Tbase 1415.78W不符，不能照引。能保留的替代机制只需针对NAS与T2Tbig这两行；其他P100×8行并非全相同。这一残余错误保留在原输出，正文明确不采纳。

可引用的判断是：**NAS与T2Tbig两行同为1515.43W；原文未明确交代这两个表值的来源映射，因此仅凭相等不能确定沿用机制。** 同理，“PDU”名称不能证明制冷边界；外部201须补计量位置、下游负载、起止时间、任务归属和因子适用地区/时段。没有边界时先unknown，不能套论文PUE或填0。
