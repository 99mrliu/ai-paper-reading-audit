# AI给了引文，为什么仍不能相信“只有这个解释”？

本文围绕Strubell等ACL2019的能耗论文，分享一个小问题：怎样识别AI把“数值兼容”写成“唯一原因”，并让它把论文估计与用户外部输入分开。不是碳排产品介绍，不重训模型，也不测实际电力。

材料包括两段真实实践：玻尔科学空间的一次两轮阅读，出现过强推断、追问修订后仍有算术错误；随后用冻结的paper-budget-audit v1.1.1，在新Codex会话中做定点验证。新会话只给原PDF、任务和Skill，不提供旧报告。它支持“本次任务完成了这些核查”，不能证明Skill导致稳定准确率提升。

## 问题怎样变成可检验的步骤

主论文为Emma Strubell、Ananya Ganesh、Andrew McCallum，Energy and Policy Considerations for Deep Learning in NLP，ACL2019，3645–3650，P19-1355。完整6页[原PDF](INPUT/paper.pdf)及[来源许可](SOURCES.md)随包。

PDF第4页Table3的BERT行是12041.51W、79h、1507kWh、1438lb；第3页正文另给79.2h。只问“为什么算不回去”容易得到一个貌似合理的故事。真正要拆开的是：显示输入是否精确复算匹配？另一时长是否与显示舍入兼容？兼容解是否唯一？有没有证据证明作者内部采用了它？四个问题不能合并。

[Skill](skill/SKILL.md)据此要求先冻结名义输入，再另存候选解释；若声称唯一，就用邻近反例或反解区间检查；外部测量和论文表值即使同数也分别记来源。脚本以Decimal统一单位与边界，缺数据返回unknown/partial，坏组件返回invalid；算术脚本不能自动证明转录、语义或测量真实性。

首答定位了PDF页码与方法，却写“只有79.2小时才成立”。我们提供79.21的构造反例，要求计算；第二轮撤回唯一性，分清论文201与外部电表201，但又写201×0.954=191.88。作者侧独立计算为191.754，仍不采纳这条答复；191.8759875984对应的是未取整201.1278696。失败没有被改写成成功。

## 作者侧核查：保留失败，再检查候选

方法式(1)/(2)在PDF第2页：能量=P×t×1.58/1000，排放=E×0.954。Power按合计IT功率解释，不再乘GPU数量。名义输入和结果见out/ledger-nominal.json、out/calculations-nominal.json；候选另存，不覆盖79小时的失败。

| --- | ---: | ---: | --- |
| 表列79h | 1503.0212782 | 1433.8822994028 | 精确值及整数舍入均不能重现1507/1438 |
| 正文79.2h | 1506.82639536 | 1437.51238117344 | 在输出整数舍入假设下兼容；PDF第3页有此时长 |

| 外部假设201kWh×历史因子 | — | 191.754 | 条件示例，不能称当地真实排放 |

反解能量显示区间[1506.5,1507.5)和排放显示区间[1437.5,1438.5)，在固定其他参数时得到上述时长交集。端点取决于取整规则；工具的封闭区间只是保守兼容包络，不是置信区间。新会话独立实现[out/independent_check.py](out/independent_check.py)，作者另保留[inverse_check.py](inverse_check.py)交叉核算；两者一致不构成独立科学测量。

如果表中79本身也是整数舍入显示，79.2仍可能同时匹配这一显示值。不能以“把79当精确输入算不回去”宣判论文科学结论矛盾。若PUE也允许变化，固定79小时还有其他参数组合，作者反解见author-check-results.json；不存在内部计算唯一识别。

本地201的物理边界未给，因此原始记录保持unknown；只有另设“设施电量”假设才得到energy可知、当地carbon仍unknown的partial记录。PDU标签不保证含制冷；共享设施归因要明确增量或分摊口径，不统一要求扣基线。完整候选结果保留，不把unknown填成0。

PDF第2页最多一天的功率采样、第3页其他论文的完整时长、第4页表值是不同证据层级。新报告自述表图已看，事件流仅明确记录生成页图，未提供独立的图像查看遥测；不能由生成PNG证明视觉核对。作者侧可回到随包整页图与原PDF检查。原作者日志、底稿和本地因子仍缺失，核查到此停止。

## 复做与验收

只检查算术及已保存产物：

```sh
python3 recheck.py
python3 inverse_check.py
```

仅需Python标准库；recheck在临时目录重建并比较9份JSON，运行22项边界测试，不修改冻结输出，不调用模型。它不自动审判科学含义。查看unknown与首轮名义残差，与通过退出码同样必要。

重新执行AI阅读：在新的空目录复制INPUT、skill及prompt.txt，准备out目录；用支持本地文件工具的AI助手提交prompt.txt，保存全部输出和工具记录。原会话使用`codex --no-daemon exec --ignore-user-config --skip-git-repo-check --ephemeral --sandbox danger-full-access -c approval_policy='"never"' --json -C <新目录> -o <新目录>/out/assistant_final.md -`，标准输入为prompt.txt。该模式无操作系统级文件围栏，运行前应在自己的受控目录检查任务与工具权限；支持更严格隔离时可采用它并如实记录差异。PDF提取需Poppler，页图生成另需PyMuPDF，准确原模型快照未知，因此不承诺逐字重放或完全相同输出。代码与规则不需联网；调用AI本身需要自己的模型服务。

验收新回答时检查三项语义，而不匹配固定措辞：是否保留79h失败并否定唯一性？是否拒绝同值推出同源？是否分清两种201、算对乘法且保留当地排放未知？任何一项失败都原样记录。science-space/REVIEW.md提供另一入口的实际复做步骤与残余错误。
