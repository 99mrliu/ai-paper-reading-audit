# 从算式正确到引用可靠：用玻尔核查一段BERT能耗笔记

我们准备在组会引用Strubell等的训练能耗估计。AI找到了表格，也运行了Python，却仍把“能算回表值”写成唯一时长，把两点拟合写成测量来源。本文解决一个阅读问题：**怎样让最终引用保留原文的估计性质、版本、单位和未知？**

真实同题首答、后续诊断、原脚本与作者核查全部保留，另做一次新可见会话的最终引用交付。笔记与外部电表为构造任务，未做新训练或能耗测量。

## 原文与方法

主论文：Emma Strubell、Ananya Ganesh、Andrew McCallum，Energy and Policy Considerations for Deep Learning in NLP，ACL2019，P19-1355，3645–3650。完整6页[原PDF](INPUT/paper.pdf)随包，CCBY4.0。版本、SHA256、授权与贡献见[SOURCES.md](SOURCES.md)。

| 原文位置 | 阅读时不能丢掉的上下文 |
| --- | --- |
| [PDF2/3646](out/source-page-2.png)，方法/式(1)(2) | 采样估算、合计/每卡、PUE1.58、0.954lb/kWh；估计不等于取得该行日志 |
| [PDF3/3647](out/source-page-3.png)，BERT/NAS段 | 正文79.2h、V100×64及其他来源；不是由表格反推的唯一真实输入 |
| [PDF4/3648](out/table3-page4.png)，完整Table3 | 79h、12041.51W、1507kWh、1438lb、Estimated限定、其他行及TPU缺值表注 |

把Power按合计IT功率处理作条件复算，不再乘64，PUE只乘一次：

```text
E(t)=12041.51 W÷1000×t h×1.58=19.0255858t kWh
C(t)=E(t)×0.954 lb/kWh=18.1504088532t lb
```

精确79h给1503.0212782kWh、1433.8822994028lb，与表不等。79.2h可在整数half-up假设下到1507/1438，79.21等也可。分别令两个显示值为精确数求解，不代替同一个时长满足所有显示约束。

在正数half-up下，表79、正文79.2、E1507、C1438反解到同一t的交集约[79.19931785705,79.23540519840)h；全部非负截断则约[79.22686544587,79.26168559814)h。精确候选是否通过，与显示79.2所代表区间是否含其他可行值不同。[Fraction脚本](matched/author_verify.py)与[严格端点](matched/author-verification.json)明示假设、开闭与共同交集；不是置信区间或已知内部舍入实现。

## 来源故事怎样从计算中长出来

首答B用T2Tbig(P100×8,1515.43W)和BERT(V100×64,12041.51W)拟合Power=a+g·b，再称NAS是同一采样功率缩放。两个参数拟合两点没有来源证明；跨硬件/负载共享参数也缺原文支持。

未参与拟合的T2Tbase(g=8,1415.78W)预测1515.43W，差99.65W。NAS与拟合点同g=8，零残差没有新增区分力。[可运行反例](matched/probe_shared_power.py)及[输出](matched/power-probe.json)只否定这个全表共享模型，不能证明另一实际生成机制。功率来源仍需逐行日志。

另一个精度陷阱：201×0.954=191.754；未舍入201.1278696×0.954=191.8759875984，两者都可显示192。191.88/0.954并不精确等于201.1278696。作者不采纳原答的强等号或内部路径解释。

## 新实践：最终引用单独验收

2026-10-28在玻尔0.10.12新可见空会话，用相同6页原件+[独立引用Skill](closure/skill/SKILL.md)核查一段构造的组会草稿。[实际提示](closure/prompt.txt)、[发送前冻结六项](closure/design-frozen.json)及[三个完整交付](closure/first-artifacts/final.md)保留；首答界面用时7m41s，准确模型/费用与后台隔离未知。

[作者复算](closure/verify_delivery.py)确认脚本/保存JSON一致，五行精确数值通过；[逐条语义核查](closure/author-review.md)却发现：数值在代码正确，在final.md变成错误的精确等号；短引用主体有来源，紧邻注释又推定内部取整路径。六项中两项通过，其余未满足完整要求，不能说“验收全部通过”。这表明验收单位应是“引用正文+紧邻条件”，而不是只抽查公式或最后一句。

[针对性反馈](closure/repair-prompt.txt)另开同会话后续轮，原三个交付冻结不改。它是已知答案反馈后的修订，不能当作独立前测或因果优势。[真实修订](closure/revised.md)改正了计算等号和来源机制，但仍把近似区间写成闭区间；作者另记残余错误。作者采用的最终引文与停止条件在核查记录中，明确与AI原答区分。

## 相近文章的版本边界

同作者AAAI2020另一文章，Energy and Policy Considerations for Modern Deep Learning Research，DOI10.1609/aaai.v34i09.7123，PDF2式(2)用0.477，PDF3/Table2列1507kWh、719lb。[必要原文与来源](version-check/README.md)、[实际追加问题](version-check/prompt.txt)、[完整原答](version-check/answer-ax.txt)、[作者判定](version-check/author-review.json)均本地保留。该旧轮只收到有限片段与标明的作者概述，未声称模型读了2020全文，也不混入A/B比较。

[精确核算](version-check/verify_versions.py)：显示1507乘0.954为1437.678，乘0.477为718.839，可取整到1438/719。因子减半不提供实际硬件耗电减半的新测量；相同估计显示也不证明真实能耗相同。片段不确立正式勘误或内部舍入顺序，原答过强断言不采纳。历史因子不直接作为当前任意地区真值。

## 在玻尔照着做

1. 文献阅读→本地导入INPUT/paper.pdf→核对6页/题名/哈希→新建对话。需要自己的账户与文件权限，准确后端和费用未知。
2. 重做旧比较时分别发送matched/task.txt和B-prompt.txt；后者等于任务+换行+流程。重做新交付时用本次保存的实际提示和Skill，替换本机绝对路径，不提前提供作者答案。
3. 保存首答、表格、脚本和结果。对照PDF2/3/4页逐句验收最终引用；后续修订另存。无功率来源、原始精度、当地因子或计量边界时停在未知，不凭设备名称判断物理边界。
4. 解析缺正文时先核对原PDF、权限与页数；可用pdftotext-layout补提取并回看图表。解析完成图标不证明方法已读；没有原文则如实限制范围。

```sh
python3 recheck.py
```

Python标准库，无网络、无模型。复算9份原JSON和22项输入边界、复跑三个真实生成脚本并与作者回放比较，再核算共同区间、功率反例和版本因子。另复跑closure/verify_delivery.py核对新交付。退出0不证明引文语义、转录或物理边界正确。

out/、INPUT/task.md、prompt.txt、session.json及skill/保留此前真实Codex定点阅读的完整必要输入输出：11条账本、名义失败/unknown，冻结Skill1.1.1，142.271秒、9次工具调用；准确默认模型未知，未在本次重跑。完整原生流按平台协议另附，不冒充玻尔UI原生遥测；命令见selected-operations.jsonl。CLI会读取自身配置/缓存，未做系统级密闭隔离。

本文贡献是实际落实“原文→条件计算→反例→来源停止条件→最终引用”。构造问题、定向流程和单次新交付不足以证明普遍准确率、因果优势、提速降本或稳定性。更进一步需要原作者逐行日志、未舍入输入、取整实现，以及当前任务的地区/时间/计量边界。
